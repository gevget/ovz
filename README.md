# Навигатор доступности — пакет инструкций для Codex

Этот набор файлов — единый source of truth для пересборки проекта в 2026 году.

## Что строим

Один web-проект из двух крупных частей:

1. **Лендинг проекта** — публичная презентация продукта для пользователей, партнёров, фондов, государства и потенциальных инвесторов.
2. **Интерактивное demo-приложение** — кликабельная симуляция мобильного приложения внутри реалистичного мокапа смартфона.

Demo не является production-приложением. Оно должно выглядеть и вести себя как настоящий продукт, но работать на локальных demo-данных без backend.

## Порядок работы Codex

Выполнять строго последовательно:

1. `00_MASTER_PRODUCT_2026.md`
2. `01_LANDING_CONTENT.md`
3. `02_LANDING_BUILD_SPEC.md`
4. `03_DEMO_APP_MAP.md`
5. `04_DEMO_APP_UX_AND_INTERACTIONS.md`
6. `05_DESIGN_SYSTEM_AND_ACCESSIBILITY.md`
7. `06_DEMO_DATA.md`
8. `07_CODEX_EXECUTION_PLAN.md`

Нельзя начинать с визуального полиша до завершения архитектуры и кликабельных сценариев.

## Основные маршруты проекта

- `/` — лендинг
- `/demo` — интерактивное demo-приложение
- `/demo?role=user`
- `/demo?role=volunteer`
- `/demo?role=partner`
- `/demo?role=admin`

## Главный критерий готовности

Человек, который впервые открывает проект, должен за 3–5 минут понять:

- какую проблему решает продукт;
- почему это не просто карта доступности;
- какие сценарии уже продуманы;
- как продукт работает для разных ролей;
- как может выглядеть реальное приложение;
- зачем проекту партнёры и инвестиции.

После этого человек должен нажать **«Открыть демо»** и самостоятельно пройти основные пользовательские сценарии.
